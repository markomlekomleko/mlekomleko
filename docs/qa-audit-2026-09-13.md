## 3. Потврђени проблеми и приоритети

P0: блокира пуштање због интегритета података. P1: поправити/довршити пре прихватања одговарајућег тока. P2: функционални, UX или квалитативни недостатак за наредни циклус.

### QA-01 — P0: гост може преписати податке регистрованог купца и адресу претплате

**Репродукција:** креирана је претплата фиктивног купца, затим је email потврђен регистрацијом. Из новог захтева без cookie-ја/сесије направљена је једнократна готовинска поруџбина са истим email-ом и другим именом, телефоном и адресом.

**Резултат:** HTTP 201; исти customer ID промењен је из `QA Original 1` у `QA Different 99`. При генерисању доставе и **стара претплата** добија нову, непотврђену адресу. Лозинка/сесија нису преузете, али су подаци и одредиште робе промењени без доказа власништва над налогом.

Узрок: [commerce.ts](</Users/luka/Documents/ChatGPT/mleko mleko v2/server/commerce.ts:283>) ради `ON CONFLICT(email) DO UPDATE` без аутентификације; [delivery пројекција](</Users/luka/Documents/ChatGPT/mleko mleko v2/server/deliveries.ts:69>) узима адресу из глобалног customer реда.

**Довршити:** раздвојити snapshot података нове поруџбине од профила/адреса постојећег купца; измене профила и претплате условити аутентификованим власником. Додати регресију са два независна корисника и провером наредне листе доставе.

Доказ: [P01 и P05](</Users/luka/Documents/ChatGPT/mleko mleko v2/artifacts/qa-2026-09-13/api-probes.json>).

### QA-02 — P1: checkout прихвата cross-origin `text/plain` упис

`POST /api/checkout` са `Origin: https://unrelated.example`, `Content-Type: text/plain` и `idempotencyKey` у JSON телу враћа **201** и уписује поруџбину. Није потребан custom header који би browser натерао на preflight.

[Checkout route](</Users/luka/Documents/ChatGPT/mleko mleko v2/app/api/checkout/route.ts:6>) не проверава Origin, а [readJson](</Users/luka/Documents/ChatGPT/mleko mleko v2/server/domain.ts:17>) не проверава media type. У комбинацији са QA-01 ово повећава ризик нежељених уписа. Довршити проверу порекла, JSON Content-Type и доказ власништва за измене постојећих података. Доказ: P02 у API JSON-у.

### QA-03 — P1: позната упозорења у runtime зависностима

- `ws@8.18.0`, преко `@libsql/client → @libsql/hrana-client → @libsql/isomorphic-ws`: high memory-exhaustion advisory; за 8.x исправка је у 8.21.0. [Званично упозорење](https://github.com/advisories/GHSA-96hv-2xvq-fx4p).
- `baseline-browser-mapping@2.10.30`, преко Next-а: moderate process-termination advisory; affected `<2.11.0`. [Упозорење](https://github.com/advisories/GHSA-w5vr-8v7q-w6rv).

Ово је потврда верзија у зависностима, не доказ да нападач може директно погодити рањиву функцију на production deployment-у. Ажурирати компатибилне зависности и поновити build, runtime и browser регресију. [Audit JSON](</Users/luka/Documents/ChatGPT/mleko mleko v2/artifacts/qa-2026-09-13/dependency-audit.json>).

## 6. Шта треба финализовати пре launch одлуке

1. **Затворити QA-01/02** и доказати да гост/други корисник не мења профил, историју ни будућу доставу постојећег купца.
2. **Усагласити приказе са стварним стањем:** CMS hero, promo у drawer-у, тренутак готовинске наплате, један извор quote-а.
3. **Довршити корисничке контроле:** focus модала, опоравак/sync корпе, трајно додавање у постојећу претплату, адресе и admin editor ако су део прихваћеног обухвата.
4. **Довршити recovery и мерење:** consent gating, комплетан recovery циклус и стварно повезан funnel без неовлашћеног праћења.
5. **Оспособити release проверу:** dependency update, одвојени generated output директоријуми, поправка застарелих тестова без брисања смислених assertion-а, регресије за сваки потврђен дефект.
